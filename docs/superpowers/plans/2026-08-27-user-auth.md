# User Authentication and Authorization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the requested asynchronous SQLite-backed user authentication and administration APIs without changing patient, record, X-ray, AI, or practice example behavior.

**Architecture:** A dedicated user router depends on small schema, service, and security modules. Async SQLAlchemy persists users and token state in SQLite; the frontend calls the documented API contract and only its user-related templates change.

**Tech Stack:** FastAPI, SQLAlchemy asyncio, aiosqlite, PyJWT, pwdlib Argon2, Pydantic, pytest, httpx.

**Spec:** `docs/superpowers/specs/2026-08-27-user-auth-design.md`

## Global Constraints

- Default persistent database is exactly `db/ai_health.db`; no credentials or users are hardcoded.
- Access JWT lifetime is 1,800 seconds and refresh JWT lifetime is 604,800 seconds.
- JWT payload contains only `user_id` plus standard `exp`.
- Refresh cookie is `HttpOnly`, `Secure`, `SameSite=Lax`, and scoped to `/api/v1/users`.
- Do not modify patient, medical-record, X-ray, AI, or `/practice_api` behavior.
- All DB access must use `AsyncSession`.
